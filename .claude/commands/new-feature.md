# Command: /new-feature

새로운 기능 개발을 시작한다. 요구사항을 분석하여 계획 문서와 기능 정의서를 자동 생성한다.

---

## 사용법

```
/new-feature "기능 설명"
/new-feature           # 대화형 모드
```

---

## 예시

```
/new-feature "사용자가 할 일을 추가하고 완료 처리할 수 있는 기능"
/new-feature "로그인 시 2FA 인증 추가"
/new-feature "대시보드에 최근 활동 위젯 추가"
```

---

## 실행 흐름

```
1. 요구사항 확인
   ├─ 인자로 전달된 경우 → 바로 진행
   └─ 인자 없는 경우 → 대화형으로 수집

2. Planner 에이전트 활성화
   └─ .claude/agents/planner.md 참조

3. generate-plan 스킬 실행
   ├─ 입력: 요구사항
   └─ 출력: specs/plan.md, specs/feature.md

4. 결과 보고
   ├─ 생성된 문서 요약
   └─ 다음 단계 안내 (/new-api)
```

---

## 생성되는 문서

### specs/plan.md (갱신)
```markdown
## [기능명]
- 목적: [왜 이 기능이 필요한가]
- 범위: [포함/제외]
- 마일스톤: [단계별 체크리스트]
- 리스크: [예상 리스크]
- 검증: [완료 조건]
```

### specs/feature.md (생성)
```markdown
# 기능: [기능명]

## 요구사항
[상세 요구사항]

## 완료 조건
- [ ] [조건 1]
- [ ] [조건 2]

## 영향 범위
- 파일: [예상 변경 파일]
- API: [필요한 API]
- UI: [영향받는 화면]

## 테스트 계획
[테스트 전략]
```

---

## 연결 명령어

| 순서 | 명령어 | 설명 |
|------|--------|------|
| 현재 | `/new-feature` | 기능 정의 |
| 다음 | `/new-api` | API 설계 (API 필요 시) |
| 이후 | `/run-tests` | 테스트 생성/실행 |
| 마지막 | `/pre-pr` | PR 준비 |

---

## 옵션

| 옵션 | 설명 | 예시 |
|------|------|------|
| --type | 작업 유형 강제 | `/new-feature --type=bug "로그인 실패"` |
| --skip-plan | plan.md 갱신 생략 | `/new-feature --skip-plan "..."` |

---

## 체크리스트

명령어 실행 후 확인:
- [ ] specs/plan.md에 마일스톤이 추가되었는가?
- [ ] specs/feature.md가 생성되었는가?
- [ ] 요구사항이 명확하게 기술되었는가?
- [ ] 완료 조건이 테스트 가능한가?
- [ ] 다음 단계가 안내되었는가?
